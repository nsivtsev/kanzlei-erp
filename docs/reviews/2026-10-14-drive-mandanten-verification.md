# BL-047 — Mandanten внутри Drive

Дата: 14 октября 2026. Ветка `codex/drive-downloads`, поверх завершённого BL-046.

## Статус

**BL-047 реализован и проверен.** Сотрудник находит доступного клиента в Drive, открывает его папку/карточку ERP и создаёт отсутствующую папку по праву изменения. DE/RU браузерная приёмка, профильные тесты и полный CI итогового образа завершились успешно. BL-048–049 и полный BL-050 остаются открытыми.

## Реализация

- `kanzlei_erp.mandant_drive.list_mandanten(search="", start=0, page_length=50)` выдаёт только читаемые текущим System User Customer. Список содержит клиентов без папки; размер страницы ограничен 1–100, поиск по имени/ID, сортировка по имени и ID. `next_start` относится к читаемым записям и не раскрывает количество отклонённых документными правами кандидатов. При дополнительной фильтрации выполняется дочитывание.
- DocShare-only читатель может не иметь полевых разрешений уровня роли. Поэтому get_list запрашивает ID, затем каждый ID проходит проверку document read, и только проверенные данные Customer читаются пакетно. User Permissions/DocShares и отсутствие прав System Manager на Customer без дополнительных ролей подтверждены тестами.
- Связи File проверяются пакетно: повреждённая/удалённая связь, не-папка, неактивный корень и чужой marker дают unavailable только для соответствующей строки. При этом отсутствуют ID/URL папки и can_create; замена не создаётся автоматически.
- Существующие get_folder/create_folder не изменены. Повторное/параллельное создание остаётся идемпотентным, связь защищена сервером.
- `/drive/mandanten` использует отдельную Vue-страницу, Sidebar/BottomBar и подтверждённый isStaff. Поиск 300 мс, страницы по 50 строк, явные состояния/повтор, создание и открытие папки в текущей вкладке, ERP в новой.
- Нет постоянного кэша списка и фонового опроса. Вход, focus/visible return и кнопка обновляют первую страницу текущего поиска. Поколения запросов и сессий исключают поздние ответы, включая потерю и восстановление той же сессии. Возврат запускает новый запрос даже при старом запросе в полёте.
- После проверки чтения Suite вызывает `drive_entity_navigation`. Kanzlei читает сохранённый marker, проверяет актуальный Customer и корень. Ответ получает необязательный mandant-контекст; сервер обрезает крошки до корня, клиент строит «Mandanten → клиент → подпапка → файл». Служебные предки не раскрываются, заголовок берётся из текущего Customer, клиентский корень не запускает inline rename. Обычные файлы сохраняют прежнюю навигацию.
